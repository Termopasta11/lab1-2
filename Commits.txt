Часть 4. Работа с ветками и конфликтами
                             Поиск кандидата
git checkout -b feature/find-by-name — создал ветку для реализации поиска кандидата по фамилии.
git add . — подготовил изменения метода findBySurname.
git commit -m "feature/find-by-name: добавлен поиск кандидата по фамилии" — сохранил реализацию поиска.
Создание и разрешение конфликта
git checkout master — вернулся в основную ветку.
git add . — подготовил альтернативную реализацию поиска searchBySurname.
git commit -m "Добавлен метод searchBySurname (master)" — сохранил изменения в основной ветке.
git merge feature/find-by-name — объединил ветки и вызвал конфликт изменений.
Merge Editor в IntelliJ IDEA — сравнил версии файлов и выбрал итоговый вариант разрешения конфликта.
git add . — добавил разрешённый файл в индекс.
git commit -m "Merge feature/find-by-name: разрешён конфликт" — сохранил результат разрешения конфликта.
git branch -d feature/find-by-name — удалил завершённую ветку поиска.
                          Удаление кандидата
git checkout -b feature/remove-by-name — создал ветку для удаления кандидата по фамилии.
git add . — подготовил метод removeBySurname.
git commit -m "feature/remove-by-name: добавлено удаление по фамилии" — сохранил реализацию удаления кандидата.
git checkout master — переключился на основную ветку.
git merge feature/remove-by-name — объединил изменения удаления с основной веткой.
git branch -d feature/remove-by-name — удалил завершённую ветку.
Подсчёт кандидатов
git checkout -b feature/count — создал ветку для подсчёта кандидатов.
git add . — подготовлен метод count.
git commit -m "feature/count: добавлен подсчёт кандидатов" — сохранилась реализацию подсчёта.
git checkout master — возвращение в основную ветку.
git merge feature/count — объединение изменения подсчёта с основной веткой.
git branch -d feature/count — удаление завершённую ветку.
git log --oneline --graph --all — просмотрена история коммитов и объединение веток в виде графа.
git status — проверена текущее состояние репозитория.
